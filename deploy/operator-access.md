# Оператор: только таймер

Миграция `038_operator_timer_only.sql` применяется вместе с обновлёнными
`admin.html`, `display.html`, `index.html`, `crm.html`, `tournaments.html`
и `js/admin-nav.js`. После выкладки обновить открытые служебные страницы и ТВ.

Оператор видит список назначенных комнат и панель таймера. Доступны старт,
пауза, смена уровня, ±60 секунд, перерыв, финальный стол и сброс часов.
Остальные вкладки скрыты; CRM и расписание перенаправляют оператора в таймер.
Завершение турнира с сохранением финансовых итогов выполняет администратор.

В базе оператор не читает и не меняет игроков, регистрации и отчёты.
Полный `rooms.state` доступен только администратору: там хранятся оплаты.
Оператор использует `vp_operator_rooms` и `vp_operator_timer`; последний
проверяет назначение и изменяет только `state.timer` и служебную метку записи,
сохраняя остальные данные комнаты. Старые RPC управления турнирами больше
не считают назначение оператора административным доступом.

ТВ и приложение игрока читают `vp_display_rooms`: только разрешённые поля
часов, структуры, общих счётчиков и публичных данных ТВ, без оплат и долгов.
Broadcast `timer_state` передаёт уведомление без состояния; получатель
перечитывает разрешённые ему данные. Новые поля не становятся публичными
автоматически: проекция использует явные списки полей.

Проверка: `tests/operator-access.test.js` (PGlite, путь через `VP_PGLITE_MODULE`).
